# 求职邮件解析与日程同步设计

本文记录 OfferLine 邮件解析与日程同步链路的完整设计，重点拆解真实求职邮箱中高频出现的异常场景，以及我们围绕「高召回、零误报、不篡改用户进度」做出的工程取舍。

## 1. 端到端处理管道

```text
IMAP INBOX (readOnly: true / EXAMINE，绝不修改邮件未读状态)
  │  按 UID 增量拉取 + messageHash 账本跳过已读邮件
  ▼
Stage 1: 内容清洗与结构保留 (extractCleanEmailText + parseIcsEvent)
  │  清 <head>/<style>/<script> · 保留 <a href> 真实外链 · 解析 .ics 附件
  ▼
Stage 2: 6 重前置门控 (硬规则拦截，零 Token 消耗)
  │  验证码/账单 · 专家平台 · 面试调研问卷 · 校招直播/群发广告 · 拒信/流程终止 · 纯投递回执
  ▼
Stage 3: 确定性规则解析 (parseRecruitmentEmailByRules)
  │  公司标准名归一化 · 岗位抽取与反幻觉 · 轮次规范化 · 三态时间识别 · 优先级链接打分
  ▼
Stage 4: 可选个人 LLM 增强 (parseRecruitmentEmail)
  │  严格枚举约束 + 服务端二次归一化与安全校验（超时/失败无损回退规则结果）
  ▼
Stage 5: 非破坏性记录关联 (inferRecordForEmail)
  │  同公司+岗位精确匹配 → 同公司唯一进行中流程 → 同集团唯一进行中流程 → 多活留空
  ▼
Stage 6: 语义去重与字段合并 (findDuplicateEmailEvent + mergeDuplicateEvent)
  │  同公司同类型同场提醒自动合并补全缺失字段，绝不重复建卡片
  ▼
Stage 7: 分模式入库与 ICS 日历导出
  │  scheduled -> 定时日程 + 30min 提醒
  │  deadline  -> 截止日期标 + 全天日历提醒 (VALUE=DATE)
  │  flexible  -> 时间自定待办，不向外部日历写入伪造时刻
```

## 2. 真实异常 Case 清单与处理策略

真实个人邮箱里的招聘邮件远比手工构造样例脏得多。下面是解析链路重点处理的 10 类真实异常：

| # | 异常现象 | 原始解析会出什么问题 | 现行处理方案 |
|---|---|---|---|
| 1 | **纯 HTML 邮件开头带大段 `<style>` CSS** | 粗暴 `replace(/<[^>]+>/g, " ")` 会把数百行 CSS 留在正文前 1000 字里，把真正的岗位、时间和拒信正文顶出截断窗口 | `htmlToCleanText()` 先完整移除 `<head>` / `<style>` / `<script>` / HTML 注释，再把块级标签转换行、表格单元格转 `\|`，并解码 HTML 实体与零宽字符 |
| 2 | **会议/笔试链接藏在 `<a href="...">点击进入</a>` 里** | 去标签直接把 `href` 剥没了，正文只剩「点击进入面试」，会议链接提取率暴跌 | 去标签前先把有效 `<a href="https://...">文案</a>` 展开为 `文案 (URL)`；同时在提取层按显式标签（`面试链接/考试地址/登录路径/测评网址/意向书链接`）优先匹配，兼容短链域名，并屏蔽图片 `.png/.svg`、客户端下载页、公众号推文与退订追踪链 |
| 3 | **面试结束后必发的「面试体验调研 / 满意度评价」** | 标题带「面试」「邀请」，很容易骗过规则甚至大模型，误建成一场新日程，甚至被标成「面试通过」 | 专设 `SURVEY_FEEDBACK_RE` 拦截，但**仅检查主题和正文前 260 字**（避开真实面试邀请正文末尾常附的「面试结束后您将收到体验调研」提示语，防误杀） |
| 4 | **校招「专场直播 / 持续招聘中 / 热招岗位」群发邮件** | 群发邮件里经常同时出现「今晚 19:00」「HR 面试重点」「笔试彩蛋」，极易被误识别为面试或笔试 | 主题未出现明确个人邀约词时，对直播/宣讲/热招/内推通道类文案硬拦截；LLM Prompt 同样显式禁止放行群发宣传 |
| 5 | **拒信 / 感谢信 / 应聘反馈通知** | 既不需要占日程表，又常没有活动时间；若强制回退用发信时间入库，会把凌晨收到的拒信变成一条 1 小时会议 | **明确策略：拒信不写入日程**。规则层用强拒信短语 + 软主题配合正文线索拦截，LLM 返回 `actionHint = "fail"` 也做兜底拦截；粘贴预览时仍会清晰告知用户「识别为拒信，已忽略」 |
| 6 | **发件人写法定全称或泛称（`招聘小秘书` / `recruitment` / `某市某某科技有限公司`）** | 卡片标题难看，且无法与用户手动录入的简称（如 `Shopee` / `大疆` / `华为`）关联，官网 Logo 也匹配不上 | 抽出前后端共用的 [shared/companies.ts](../shared/companies.ts)：维护 60+ 主流企业标准名、域名、Moka 租户前缀（`xxx-no-reply@mail.mokahr.com`）、法定公司后缀剥离与泛称黑名单，统一归并为标准简称 |
| 7 | **大厂面试邀请不写轮次，或只给日期/时长/双横线格式** | 多轮面试标题一模一样，硬猜成「一面」会误导用户；`19:00:00 -- 21:00:00` 或分两行的 `开始时间/结束时间` 会丢结束时间 | 邮件未写明第几轮时，阶段名**如实标为 `面试`**，不臆测「一面」；时间解析依次支持 `.ics` 附件、双行起止时间、表格管道符、双横线与秒位、`考试时长/预计面试时长` 自动推算结束时间 |
| 8 | **在线测评与录用意向书没有固定开会时刻，正文末尾却有落款时间** | 一旦把发信时间或落款时间当 `startAt`，日历里会冒出一条莫名其妙的 1 小时会议；没写岗位时大模型还可能把「2027届校园招聘」编成岗位 | 引入三态 `timeMode`：`scheduled`（明确起止时刻）、`deadline`（`xx日前确认` 或 `有效期 N 个自然日`）、`flexible`（不限时尽早完成）；反落款时间校验跳过与发信时刻相差 10 分钟内的未标注时间戳；`cleanPosition()` 屏蔽届别/招聘季伪岗位 |
| 9 | **同一场笔试/面试由考试平台连发 2～3 封提醒邮件** | 仅按 `Message-ID` 去重拦不住重发提醒，待确认列表和日历里直接多出 3 条一模一样的记录 | 入库前做**语义去重**：同归一化公司 + 同类型 + 固定时刻相差 ≤ 30 分钟（或非固定时刻 10 天内同岗位/无岗位）直接合并到已有日程，只补全缺失的链接、岗位、关联记录或更具体的轮次，不新增重复卡片 |
| 10 | **专家平台签约 / 非求职评估通知** | 来自知名大厂域名的非求职业务（如专家智囊团评估签约）容易沾大厂域名光 | 拦截非求职专家平台特征，并要求必须同时命中真实求职事件类型（面试/笔试/测评/Offer），仅凭企业域名绝不触发建日程 |
| 11 | **纯投递回执正文附带「全流程介绍」** | 标题是「欢迎投递」，但正文写了「简历初筛 → 在线测评 → 笔试 → 面试」，规则误判成测评通知 | 增加主题层投递回执门控（`PURE_RECEIPT_SUBJECT_RE`）：标题明确是投递回执且不含个人邀约词时，直接忽略正文里的通用流程介绍 |
| 12 | **日期与时刻拆成两行 + 站点括号标签（`【上海场】`）+ 中文数字有效期（`七日内有效`）** | 分行 `面试日期 / 面试时间` 解析失败；`【上海场】` 被当成公司名；`将于...失效` 和 `两日/七日内` 漏抽截止日期 | 新增分行日期时刻合并解析；将城市站点标签与 `iTalent招聘助手` / `智联推荐` 列入泛称黑名单，且企业域名优先级高于无括号主题前缀；截止正则覆盖 `将于...失效`、中文数字天数和小时预约窗口 |

## 3. 解析兜底：顺手核对与一键编辑入口

无论规则和大模型多强，面对层出不穷的第三方招聘平台模板，邮件原文仍可能缺少轮次或存在表述歧义。OfferLine 把「用户顺手修正」作为一等公民内置到所有日程入口：

- **概览页与日程页的待确认通知**：每条卡片提供 `加入日程`、`编辑`、`去更新进度`（若已关联投递）和 `忽略` 四个直觉动作；
- **三合一编辑弹窗（`EventModal`）**：顶部附原邮件主题与摘要供对照；支持随时修改公司/岗位/日程类型/轮次（附 10 个常用轮次快选芯片）、切换三态 `timeMode`（`固定时刻 / 截止日期 / 时间自定`）、随时改绑或解绑投递记录；对 `pending_confirm` 邮件提供一键「保存并加入日程」；
- **已确认日程行**：同样保留编辑图标，面试改期或补填会议链接无需删掉重建。

## 4. 为什么去掉「自动同步时间线」，改用「单活推断 + 手动点节点」

早期版本在待确认通知上提供过「确认并同步进度」按钮，点击后由后端自动把邮件对应的投递记录推进到某阶段，匹配不到公司时还会自动新建一条投递记录。经过真实邮箱验证，这种激进自动化存在三类不可控风险：

1. **邮件天然缺信息**：不少大厂面试邀请只写「面试邀请」不写第几轮，部分在线测评与录用意向书正文甚至根本不提岗位名称。
2. **盲目推阶段破坏用户状态**：用户可能已在二面或三面，收到一封未标注轮次的通知若被强行按「一面」推进，会把时间线写乱；公司名写法稍有差异还会静默造出重复记录。
3. **误写成本远高于点一下的成本**：在 OfferLine 的横向时间线上手动点一个阶段圆点只需要 1 秒，而自动改错后的排查与回滚很烦人。

因此系统采用**职责清晰的非破坏性设计**：

- **邮件只管日程，绝不自动篡改投递时间线、绝不静默新建投递记录**。
- **三层只读关联推断（`inferRecordForEmail`）**：
  1. **同公司 + 岗位关键词重合**：优先匹配状态为进行中（`status === "active"` 且未终止）的记录。
  2. **同公司唯一进行中流程**：现实里大多数人在同一家公司同一时间只会推进一个岗位；当邮件没写岗位（或岗位表述略有差异），且该公司下**恰好只有 1 条进行中流程**时，自动关联该记录并回填岗位名展示。
  3. **同集团唯一进行中流程**：利用 `shared/companies.ts` 的集团归属映射（如 `阿里云 ↔ 阿里巴巴`、`抖音/飞书 ↔ 字节跳动`、`海思 ↔ 华为`），在同公司无直接命中时按集团唯一进行中流程兜底。
  4. **多活不乱猜**：若同一公司下有 ≥ 2 条并行进行中的岗位，且邮件没写出足以区分的岗位词，宁可留空 `recordId`，绝不张冠李戴。
- **前端体验闭环**：待确认通知和日程行上直接展示推断出的 `关联：公司 岗位` 标签和「去更新进度」按钮，点击一键跳到投递页并自动筛选到该公司，由用户亲自确认点下目标阶段节点。

## 5. `timeMode` 与日历导出的对应规则

外部日历（Apple 日历 / Google 日历 / Outlook）最怕被垃圾假时间污染，因此 `server/ics.ts` 按 `timeMode` 严格分流：

| `timeMode` | 典型场景 | 页面展示 | `.ics` 日历订阅行为 |
|---|---|---|---|
| `scheduled` | 视频/现场面试、固定场次在线笔试 | 精确起止时刻 + 时长 + 迷你月历刻度 | 标准定时 `VEVENT`（`DTSTART`/`DTEND`）+ 提前 30 分钟 `VALARM` |
| `deadline` | 录用意向书确认截止、限 N 日内完成的测评 | `截止 M月D日` + 日历日期刻度 | 全天事件 `DTSTART;VALUE=DATE` + `[截止]` 标题前缀 + 提前 12 小时提醒 |
| `flexible` | 无固定时刻也无截止日期的测评或随时跟进项 | 归入「时间自定（尽早完成）」，不占迷你月历刻度 | **不导出进 `.ics`**，避免用发信时间伪造日历日程 |

## 6. 个人大模型增强适配（可选，支持无 IMAP 独立启用）

系统零 Token 纯规则已经能应对绝大多数主流招聘平台邮件；对于极少数非常规排版、英文长信或复杂改期沟通，用户可在「邮箱监听 → 大模型增强」页签自配个人 OpenAI 兼容模型（`server/llm-client.ts`）：

- **零依赖独立配置**：`PUT /api/mail/llm-config` 与 IMAP 配置解耦，不接入邮箱的用户也可单独配置模型供「粘贴邮件即时解析」使用；IMAP 后台同步与粘贴预览自动共用同一套加密凭据。
- **6 家常用厂商一键预设 + 智能 URL 归一化**：内置 DeepSeek、通义千问（百炼）、智谱 GLM、月之暗面 Kimi、OpenAI 与自定义兼容预设；`normalizeLlmEndpoint()` 自动兼容裸域名（补 `/v1/chat/completions`）、带版本路径（`/v4`、`/compatible-mode/v1`、`/v1beta/openai`）或完整 URL（绝不重复拼接）。
- **低成本前置门控与即时连通测速**：验证码、账单、拒信、调研问卷、校招宣传与纯投递回执在规则阶段即 0 Token 拦截，仅高疑似求职邮件才调用模型；提供 `POST /api/mail/test-llm` 实时测量端到端延迟与 JSON 兼容模式，避免密钥失效静默回退而不自知。
- **协议容错与安全防护**：
  - 优先发送 `response_format: { type: "json_object" }`，遇第三方中转站或旧模型返回 `400/422` 自动降级重试一次并用括号配对扫描器（`extractJsonObject`）剥离 `<think>` 思考块与 Markdown 围栏提取 JSON；
  - 复用 `brand-icon.ts` 的 DNS + IPv4/IPv6 私网拦截，默认禁止指向 `127.0.0.1`、RFC1918 内网与云元数据 `169.254.169.254`（`redirect: "error"`），自托管如需连本地 Ollama/vLLM 可显式配置环境变量 `ALLOW_LOCAL_LLM=true`；
  - 模型输出强制再过服务端公司名归一化、轮次 10 枚举收口、伪岗位清洗、拒信兜底与外链消毒；超时（15s）或上游异常无损回退本地规则。

## 7. IMAP 只读与隐私约束

- 无论是「测试连接」还是「同步邮箱」，一律以 `client.getMailboxLock(folder, { readOnly: true })`（IMAP `EXAMINE` 模式）打开收件箱，**绝不会把用户未读邮件标为已读**，也绝不删除或移动任何邮件。
- 邮件解析结果只保留标题、时间、链接与最多 180 字的清洗摘要；原始邮件全文不落库。
- 仓库内所有单元测试与示例文档均使用 100% 虚构脱敏数据。
